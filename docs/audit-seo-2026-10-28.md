# Audit SEO — nokhba.net.ly — 28 octobre 2026

> **Objet.** Le trafic organique ne progresse pas alors que le site s'est
> recentré sur deux activités : **agence web** (Tripoli + international) et
> **boutique de codes numériques** (cartes cadeaux gaming, recharges, clés
> logicielles). Cet audit identifie les causes, documente les correctifs
> livrés dans cette branche, et liste ce qui reste à faire — dans le code et
> hors du code.
>
> **Périmètre mesuré.** Production `https://nokhba.net.ly` (déploiement
> antérieur à cette branche) et build local de la branche
> `arena/011c5205-mon-site` (Next.js 16 / React 19, 62 URLs au sitemap local,
> 399 fiches produit en production).

---

## 1. Résumé exécutif

Cinq causes expliquent l'absence de progression, par ordre d'impact.

| # | Cause | Preuve | Impact |
|---|-------|--------|--------|
| 1 | **Le site n'est pas indexé** | La requête `site:nokhba.net.ly` ne renvoie **aucune** URL du site sur les moteurs interrogés ; une recherche sur le domaine ne remonte que des pages GitHub. | Aucun clic organique possible, quel que soit le travail on-page. |
| 2 | **La production parle anglais à un marché arabophone** | `<title>` et H1 de la home en anglais (« Your pro website ready in days not months ») ; `appearance.defaultLocale = "en"` était stocké en base et écrasait la langue du marché. | Les requêtes réellement tapées (« تصميم مواقع طرابلس », « شحن ببجي ») ne trouvent aucune correspondance. |
| 3 | **La boutique — le principal gisement de trafic — est invisible** | 399 produits affichés sur `/codes`, mais **10 URLs produit** seulement au sitemap ; fiches production de ~100 mots quasi identiques (« Top-up for PUBG Mobile (Auto)… »). | 85 % du catalogue n'est jamais soumis ; les fiches soumises sont du contenu mince/dupliqué. |
| 4 | **Positionnement mono-activité** | La home ne mentionnait ni `/codes` ni les codes numériques ; le lien du menu était masqué sous 1280 px (donc absent sur la majorité des portables et sur tous les mobiles) ; l'entité `Organization` se décrivait uniquement comme « Premium Web Agency ». | Google ne comprend pas que le site vend aussi des codes ; aucune passerelle entre les deux univers. |
| 5 | **Signaux de confiance dégradés** | Avis `aggregateRating` 4.9/86 auto-déclarés, e-mail public `contact@nukhba.net.ly` invalide (domaine sans DNS), `lastmod` du sitemap = date de build sur 53 entrées. | Les avis ne sont pas éligibles ; un e-mail mort et des dates fictives réduisent la confiance (crawler et humain). |

**En une phrase :** les réglages on-page n'étaient pas le problème principal —
le site n'était pas indexé, parlait la mauvaise langue pour son marché, et la
moitié de son catalogue n'était pas exposée.

## 3. Constats détaillés

### P0 — Bloquants

#### 3.1 Non-indexation
- **Constat.** `site:nokhba.net.ly` = 0 résultat sur les moteurs interrogés.
  Une recherche sur le nom de domaine ne renvoie que des pages GitHub (PR,
  README). Aucun backlink éditorial détectable.
- **Pourquoi c'est bloquant.** Sans indexation, aucune optimisation de titre,
  de contenu ou de maillage ne produit de trafic. Google doit d'abord
  découvrir, explorer et faire confiance au domaine : c'est un travail de
  Search Console + autorité, pas de balises.
- **Correctifs code livrés.** Sitemap qui déclare enfin le catalogue réel,
  dates `lastmod` honnêtes, suppression des avis auto-déclarés, e-mail et
  entité cohérents (voir §4).
- **Reste à faire (hors code).** Search Console (vérification + sitemap +
  inspection d'URL), Bing Webmaster + IndexNow, Google Business Profile,
  premiers backlinks (§5).

#### 3.2 Langue servie ≠ langue du marché
- **Constat.** En production, la home est servie en **anglais** : titre
  « Website & Store Design in Tripoli — 7 Days, Paid in USDT | Nukhba نخبة »,
  H1 « Your pro website ready in days not months ». La cause : l'ancien champ
  `appearance.defaultLocale` était stocké à `"en"` en base et primait sur le
  marché (`market.id = "ly"`).
- **Conséquence double.**
  1. Le site ne peut pas se classer sur les requêtes arabes, qui portent
     l'essentiel de la demande locale.
  2. La version arabe existe pourtant (client) mais **n'a pas d'URL** : elle
     est invisible pour Google, et l'anglais n'a pas non plus d'URL dédiée.
     Résultat : une seule version indexable, dans la mauvaise langue.
- **Correctifs livrés.** `siteLocale()` priorise `appearance.primaryLocale`
  (`"auto"` par défaut) puis la langue du marché ; `<html lang>`, titres,
  descriptions, Open Graph et JSON-LD sont alignés sur cette valeur. L'admin
  expose désormais un choix explicite « auto / arabe / anglais ».
- **Reste à faire (architecture).** Une vraie version anglaise indexable
  (`/en/...` + `hreflang`) reste à construire ; c'est un chantier de
  restructuration de routes, hors périmètre de cet audit.

#### 3.3 Catalogue invisible et fiches minces
- **Constat production.** `/codes` affiche **399 produits**. Le sitemap n'en
  déclare que **10**. Les fiches réelles (`/codes/fzr-…`) contiennent
  ~100 mots génériques : « Game Top-Up — PUBG Mobile (Auto) », « Top-up for
  PUBG Mobile (Auto) — instant delivery to your e-mail after payment. »
- **Pourquoi c'est bloquant.** Google reçoit 399 pages quasi identiques,
  85 % non déclarées. C'est le profil exact du « contenu à grande échelle »
  que les politiques anti-spam 2024 visent, et le meilleur moyen de faire
  plafonner tout le domaine.
- **Correctifs livrés.**
  - Le sitemap déclare toutes les fiches **pourvues d'un prix ou vendables**
    (au lieu des 10 fiches de repli), avec l'image de chaque produit.
  - Chaque fiche reçoit un **contenu unique dérivé des données réelles** :
    tableau des montants et prix, régions, type d'identifiant requis, étapes
    d'activation, FAQ (5–6 questions), produits liés. Les fiches de démonstration
    passent de 258–305 à **436–519 mots** (mesure locale) ; les fiches
    fournisseur de production (~100 mots) gagnent le même bloc, soit environ
    400 mots utiles supplémentaires.
  - Les noms fournisseur sont nettoyés : « Game Top-Up — PUBG Mobile (Auto) »
    devient « PUBG Mobile » dans le H1, le titre et le schéma.
- **Reste à faire.** Pagination du rayon (<https://nokhba.net.ly/codes> rend
  399 cartes sur une page — plusieurs centaines de Ko de HTML, estimation
  ~1,2 Mo avec le JSON-LD), pages de catégories crawlables
  (`/codes/steam`, `/codes/recharges`…), et enrichissement éditorial des
  familles à forte demande (voir §6).

### P1 — Qualité et cohérence

#### 3.4 Positionnement et maillage
- La home ne reliait pas `/codes` ; le menu masquait la boutique sous 1280 px.
- Aucune passerelle depuis les guides (`/blog/*`) vers la boutique.
- `/products` et `/apps` (pages « bientôt ») n'offraient aucun chemin vers
  les produits déjà en vente.
- **Livré.** Bloc « boutique numérique » sur la home (6 produits + prix
  d'entrée + CTA, rendu serveur), lien menu visible à toutes les largeurs,
  carte « boutique » dans chaque guide, bandeau « disponible maintenant » sur
  `/products` et `/apps`, entité `Store` + `ItemList` + FAQ sur `/codes`,
  `Organization` élargie au commerce de codes.

#### 3.5 Titres, descriptions, marque
- Avant : titres jusqu'à 75+ caractères, marque répétée (« … — Nukhba |
  Nukhba نخبة »), metadata en anglais sur des pages arabes et inversement.
- **Livré.** `serpTitle()` borne à 60 caractères, coupe à une ponctuation
  naturelle (`؟`, `—`) plutôt qu'au milieu d'un mot, et n'ajoute la marque
  qu'une fois ; `serpDescription()` borne à 155. Les 62 URLs mesurent
  **22–60 caractères** de titre et **95–154** de description, dans la langue
  du document.

#### 3.6 Données structurées
- `Product` : ajout de `image`, `sku`, `category` localisée, `brand` corrigée
  (plus de marque « Mobile »), `hasMerchantReturnPolicy` (codes non
  remboursables après livraison, lien vers `/remboursement`), disponibilité
  dérivée du statut (`InStock` / `PreOrder`).
- `Store` + `OfferCatalog` sur `/codes` ; `ItemList` des produits ;
  `FAQPage` identique au bloc visible sur le rayon et chaque fiche.
- **Avis auto-déclarés retirés.** Depuis 2019, Google n'affiche pas les avis
  qu'une entreprise publie sur sa propre page ; les baliser n'apporte rien et
  expose à un signalement « données structurées trompeuses ». Les témoignages
  restent visibles dans la page. Les avis éligibles sont ceux d'une fiche
  Google Business Profile vérifiée.
- `BlogPosting` : `headline`, `name`, `description`, `inLanguage` et
  `articleSection` suivent désormais la langue réellement servie.

#### 3.7 Sitemap et exploration
- `lastmod` = date de build sur 53 entrées → Google apprend à l'ignorer.
- **Livré.** Dates réelles uniquement (mise à jour d'article, capture de
  démo) ; `revalidate = 60` ; les fiches produit sans prix ne sont plus
  soumises ; `robots.txt` exclut les parcours transactionnels
  (`/codes/commande`, `/abonnements/suivi`, `/pay/*`).

#### 3.8 Pages minces
- `/abonnements` : 253 mots → **474** (tableau tarifaire, 5 questions
  fréquentes, FAQ structurée, liens vers `/pricing` et `/contact`).
- `/products` (559 mots) et `/apps` (537) restent des pages d'attente :
  assumées comme telles, elles renvoient maintenant vers la boutique ouverte.

## 5. Actions hors code (à faire par le propriétaire)

Ces actions ne peuvent pas être faites depuis le dépôt ; sans elles, les
correctifs ci-dessus ne produiront pas de trafic.

1. **Déployer cette branche.** La production tourne encore un build
   antérieur : titres anglais, anciens slugs, 10 fiches produit au sitemap.
2. **Google Search Console.** Vérifier la propriété (la balise
   `google-site-verification` est déjà émise par le layout), soumettre
   `https://nokhba.net.ly/sitemap.xml`, puis *Inspection d'URL →
   Demander l'indexation* pour les 10 pages prioritaires : `/`, `/codes`,
   `/demos`, `/services`, `/pricing`, `/sectors`, `/blog`, `/compare`,
   `/codes/<3 produits phares>`.
3. **Lire le rapport « Indexation des pages ».** La raison exacte
   (« Explorée, actuellement non indexée », « Détectée, actuellement non
   indexée », « Exclue par une balise noindex »….) détermine la priorité.
4. **Bing Webmaster Tools + IndexNow.** Bing alimente aussi ChatGPT et
   Copilot ; soumettre le sitemap et activer IndexNow.
5. **Google Business Profile** (catégorie « Concepteur de sites web »,
   adresse et téléphone identiques à ceux du site). C'est le levier n° 1 du
   SEO local à Tripoli et la seule source d'avis éligibles.
6. **Corriger `contact@nukhba.net.ly`.** Le domaine n'a pas d'enregistrement
   DNS pour ce mail (ENOTFOUND) ; les MX réels de `nokhba.net.ly` pointent
   vers Zoho. Utiliser une boîte existante, ou créer l'alias.
7. **Premiers backlinks** : badges clients (`/badge`), profils sociaux
   cohérents (Instagram, Facebook, TikTok), annuaires locaux, partenaires,
   2–3 mentions presse/blog. Un domaine sans lien entrant reste lent à
   indexer.
8. **Vérifier les promesses affichées** (« 120+ sites », « 4.9/5 »,
   « 99 % de satisfaction »). Elles sont visibles mais non vérifiables ; à
   étayer (captures, avis publics) ou à retirer.

## 6. Feuille de route 30 / 60 / 90 jours

### Semaine 1 — débloquer l'indexation
- Déployer, vérifier GSC, soumettre le sitemap, demander l'indexation des
  10 URLs clés.
- Créer la fiche Google Business Profile et demander 5 avis clients réels.
- Corriger l'e-mail public.

### Mois 1 — couvrir la demande réelle
- **Pagination du rayon `/codes`** : 48 produits par page
  (`/codes?page=2`) avec canoniques et liens de pagination, pour alléger le
  HTML et concentrer le crawl.
- **Pages de catégories** : `/codes/steam`, `/codes/playstation`,
  `/codes/recharges`, `/codes/cles-logiciels` — chacune avec 150–300 mots
  éditoriaux, le `ItemList` de sa famille et un maillage vers les fiches.
- **Enrichir 20 fiches à forte demande** (PUBG, Free Fire, Steam, Roblox,
  PlayStation, Xbox, Minecraft) avec un paragraphe propre à la plateforme,
  les régions et un guide d'achat. Laisser le reste indexable mais hors
  sitemap tant qu'il n'est pas enrichi.
- Publier 2 guides : « شحن ببجي في ليبيا — المناطق والأسعار »,
  « بطاقة Steam: أي منطقة تختار؟ ».

### Mois 2–3 — élargir et mesurer
- **Version anglaise indexable** : routes `/en/...` + `hreflang`
  `ar-LY` / `en` / `x-default`. C'est le seul moyen de capter la clientèle
  internationale que la home revendique.
- **Netlinking** : un lien dofollow par site livré (badge déjà prévu),
  2 partenariats locaux par mois.
- **Mesure** : positions moyennes, impressions, CTR, pages indexées,
  sessions organiques, panier boutique. Objectif réaliste à 90 jours :
  toutes les pages principales indexées, 100–300 sessions organiques/mois
  sur les requêtes de marque et de niche.

## 7. Garde-fous ajoutés à `npm run seo:check`

Le script échoue désormais si :

- un `title` dépasse **60 caractères** ou répète la marque ;
- une description dépasse **160 caractères** ;
- la **langue du titre** ou de la **description** ne correspond pas à
  `<html lang>` ;
- `og:locale` contredit `<html lang>` (le test ne portait que sur la
  présence) ;
- la **canonique** pointe vers une autre page que celle testée ;
- une fiche produit n'a pas de `Product` avec image/`sku`/`priceCurrency`,
  ou pèse moins de **400 mots**, ou ne renvoie pas vers `/codes` ;
- le rayon `/codes` n'a pas de `Store` ni d'`ItemList` (détection récursive,
  l'`ItemList` étant imbriqué dans `CollectionPage`), ou moins de 650 mots ;
- le sitemap contient des `lastmod` futurs ou une même date sur plus de
  80 % des entrées (signature d'une date de build) ;
- un `ProfessionalService` déclare des avis auto-déclarés (avertissement).

## 8. Ce qui n'a **pas** été fait (et pourquoi)

| Sujet | Raison | Recommandation |
|---|---|---|
| URLs localisées `/en/...` + `hreflang` | Restructuration de toutes les routes (dizaines de pages, métadonnées, maillage) ; risque de régression élevé en une passe. | Chantier dédié, mois 2. |
| Pagination du rayon | Touche le composant client de filtrage/tri ; à faire avec tests de non-régression dédiés. | Mois 1, avec les pages de catégories. |
| Traduction arabe des noms de jeux (« ببجي », « فري فاير ») | Nécessite une table éditoriale validée (risque d'erreurs de marque). | Mois 1, sur les 20 jeux les plus demandés. |
| Suppression des slugs `fzr-…` | 399 URLs déjà en ligne ; renommage = 399 redirections 301 à tester. | Après stabilisation de l'indexation. |
| Refonte des images de la home (`w=3840`) | Le `sizes` est correct (le navigateur choisit 1080/1920) ; le `src` large n'est qu'un repli. | Mesurer le LCP réel avant d'agir. |

## 9. Reproduire les mesures

```bash
npx tsc --noEmit
npm run build
npm run test:seo
npm run test:subscriptions
npm run test:digital
npm start -- -H 0.0.0.0 -p 3000       # dans un autre terminal
BASE_URL=http://localhost:3000 npm run seo:check
```

Le crawl complet (62 URLs, H1, titres, descriptions, mots, images sans alt,
liens internes) est reproductible avec le script Python de l'audit
(`/tmp/crawl.py` dans la session) : il s'appuie uniquement sur le sitemap
local et n'écrit rien dans le dépôt.
